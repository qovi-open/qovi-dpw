Qovi DpW — le trousseau ouvert par Qovi

Votre trousseau de mots de passe intuitif, ouvert par Qovi sans mot de passe maître, synchronisé sans cloud par QR entre PC et mobile. Windows Linux Android

Ce qu'il vous faut

  • L'app Qovi sur votre téléphone, avec votre compte Qovi.
  • Qovi DpW sur chaque appareil où vous voulez vos mots de passe : PC Windows (installeur .msi), PC Linux (paquet .deb) et téléphone Android (.apk).

Installer

🪟 Windows

Ouvrez qovi-dpw.msi. Windows peut afficher « éditeur inconnu » : choisissez Informations complémentaires, puis Exécuter quand même. DpW s'installe dans Program Files, avec un raccourci dans le menu Démarrer et sur le bureau.

🐧 Linux

Pour Debian, Ubuntu et leurs dérivées, en 64 bits (amd64). Dans un terminal, depuis le dossier où vous avez téléchargé le paquet :

sudo apt install ./qovi-dpw.deb

apt installe aussi ce qui manque (bibliothèque GTK 3). DpW s'installe dans /opt/qovi-dpw, avec une entrée Qovi DpW dans le menu des applications ; on peut aussi le lancer par la commande qovi-dpw. Pour le retirer : sudo apt remove qovi-dpw (votre trousseau, rangé dans votre dossier personnel, n'est pas effacé).

🤖 Android

Ouvrez qovi-dpw.apk et autorisez l'installation depuis cette source si le téléphone le demande.

L'APK est signée par « Qovi DpW » (empreinte SHA-256 du certificat : 69:F1:46:20:5E:D6:40:C6:65:73:B4:E4:A9:5D:5C:4E:69:27:23:EB:DA:C7:5D:9A:DE:BC:26:C1:30:07:9E:D6). Une APK signée autrement n'est pas la nôtre.

Une nouvelle version s'installe par-dessus l'ancienne : vos mots de passe sont gardés.

Ouvrir le trousseau

1
Saisissez votre adresse e-mail Qovi. Elle est retenue pour la prochaine fois ; le ✕ à côté l'oublie.
2
Touchez le grand bouton d'entrée.
3
Validez la demande dans l'app Qovi sur votre téléphone.
Aucun mot de passe maître à retenir : c'est votre validation Qovi qui ouvre le trousseau. La toute première ouverture sur un appareil peut prendre jusqu'à une minute.

Utiliser

  • Rechercher : tapez un ou plusieurs mots. « banque ch » trouve les entrées qui contiennent les deux mots, dans le nom ou dans la note, sans tenir compte des majuscules ni des accents. Le ✕ efface la recherche.
  • Sur chaque ligne, quatre gros boutons : ✏ ouvrir la fiche ; 👤 copier l'identifiant ; 🔑 copier le mot de passe (effacé du presse-papiers après 30 secondes) ; ↗ ouvrir le site, si l'entrée a une adresse web.
  • + crée une entrée, avec un mot de passe fort déjà proposé.
  • Dans la fiche : 🗑 supprime, ✓ enregistre, ← revient sans enregistrer.

Synchroniser vos appareils, sans cloud

1
Sur les deux appareils, ouvrez DpW avec le même compte.
2
Touchez ⟳ sur les deux.
3
Sur l'un, touchez Envoyer : un QR s'affiche. Sur un ordinateur (Windows ou Linux), c'est le seul bouton : c'est le téléphone qui scanne.
4
Sur le téléphone, touchez Recevoir et scannez le QR.

Les deux appareils finissent avec le même trousseau. Si une entrée a été modifiée des deux côtés, les deux versions sont gardées : l'une porte la mention « copie du … », à vous de choisir. Une suppression se propage aux autres appareils.

Réglages

Touchez Qovi DpW en haut de l'écran :

  • Langue : FR, DE, IT ou EN.
  • Verrouillage après inactivité : 5 min, 15 min, 30 min, 1 h ou 2 h.
  • Ancien trousseau DpW (fichier _DpW.aes) : Choisir le fichier, puis Importer avec son ancienne clé. Le fichier d'origine n'est pas modifié.

Sécurité

  • Le trousseau est stocké uniquement sur vos appareils, chiffré. Rien n'est gardé dans un cloud.
  • Il se verrouille seul après une période sans activité (60 minutes par défaut) et DpW revient à l'écran d'ouverture.
  • Le bouton de sortie, en haut à gauche, verrouille tout de suite.

L'idée

DpW montre comment une application sans serveur à elle et sans clé privée de site peut s'appuyer sur Qovi pour ouvrir un coffre local. Le client (Flutter : Windows, Linux et Android, même code) est fourni en sources ; le service DpW côté serveur fait partie de la plateforme Qovi.

1. Ouvrir sans clé privée : le parcours « Alone »

Une app de bureau ou mobile ne peut pas garder de clé privée de site : elle serait lisible par quiconque possède l'app. DpW n'embarque donc que des valeurs publiques : la clé Alone du kit et la clé publique du site DpW.

1. CH1 GET <api>/RST/SiT_1_Edr?P=… ─▶ Qovi demande d'ouverture (clé Alone + clé publique du site) 2. CH4 TLS <api>:6404 ─▶ Qovi attente du GO (130 s), en G1 : kid (empreinte) + G1(i:1), puis G1(i:2) ◀─ Qovi l'usager valide sur son mobile 3. CH5 TLS <dpw>:6999 ─▶ DpW remise de la clé du trousseau SoK.U, chiffrée avec Ch5.U issue de la validation

Sur CH4, la clé de transaction Prv_NaP ne circule jamais : la 1re trame porte son empreinte kid = 16 premiers octets de HMAC-SHA256(Prv_NaP, "qovi-ch4-kid"), puis les messages en G1 avec la clé HMAC-SHA256(Prv_NaP, "qovi-ch4-gcm"). Si le canal est coupé pendant l'attente (par exemple quand l'usager passe dans l'app Qovi du même téléphone), DpW se reconnecte et renvoie i:1 seul : le serveur renvoie alors le GO déjà donné, sans relancer le vote.

La clé du trousseau est gardée par le service DpW, par compte (table dpw_keys). Tous les appareils d'un même compte reçoivent la même clé : c'est ce qui permet la synchro. Elle n'est jamais écrite sur disque côté client ; elle disparaît au verrouillage.

2. Le coffre local

  • Fichier dans le stockage privé de l'app, invisible pour l'usager.
  • Format : "DPW2" + nonce (12) + AES-256-GCM(JSON) + tag (16), clé = HMAC-SHA256(SoK.U, "qovi-dpw-vault-v2"), "DPW2" en données associées. Un fichier modifié ou une mauvaise clé est refusé.
  • Écriture atomique (fichier temporaire puis renommage) et 3 sauvegardes tournantes. Un fichier illisible n'est jamais écrasé.
  • Contenu : {"v":3,"cod":[entrées],"del":[traces de suppression]}.

3. La synchro par QR, sans cloud

L'appareil A affiche le QR, l'appareil S le scanne. A tire une clé de session en deux moitiés, MSB et LSB (2 × 128 bits).

Étape 4 A ─▶ DpW LSB + trousseau de A (chiffré avec la clé de session) QR A ─▶ S "DPWS" + MSB + code de transfert (MSB ne passe JAMAIS par le serveur) Étape 5 S ─▶ DpW code ; reçoit LSB + trousseau de A, fusionne, dépose son trousseau Étape 3 A ─▶ DpW récupère le trousseau de S et fusionne
Le service ne détient jamais la clé de session complète : il relaie des blocs qu'il ne peut pas lire. Les blocs sont en AES-256-GCM. Le service vérifie que A et S sont ouverts sur le même compte, et le QR est à usage unique.

Fusion (règle B), symétrique

merge(a, b) = merge(b, a) : les deux appareils finissent identiques.

  • Une entrée modifiée d'un seul côté : le changement est pris.
  • Modifiée des deux côtés : les deux sont gardées, la plus ancienne en « copie du … ».
  • Une suppression se propage, sauf si l'entrée a été modifiée après. Les traces de suppression sont gardées 1 an.

4. Construire

# Android
flutter build apk --release
# Windows, puis l'installeur MSI avec WiX 5
flutter build windows --release
wix build windows/installer/Product.wxs -arch x64 -d Ver=3.0.1 -d Rel=<dossier Release> -d Ico=<app_icon.ico>
# Linux (Debian/Ubuntu amd64), puis le paquet .deb
flutter build linux --release
bash tool/build_deb.sh 3.0.1 <dossier de sortie>
# Tests : fusion, transfert, import WL, filtre, enveloppes G1
flutter test

Sécurité

  • Aucune clé privée dans l'app : seulement la clé Alone et la clé publique du site.
  • Clé du trousseau en mémoire seulement, effacée au verrouillage (60 min d'inactivité par défaut, réglable) avec le presse-papiers.
  • Mot de passe copié : effacé du presse-papiers après 30 s, et à la fermeture.
  • Canaux chiffrés et authentifiés : CH4, CH5 et la synchro utilisent l'enveloppe G1 = "G1" + base64(nonce 12 + AES-256-GCM + tag 16), avec une clé dérivée par usage (HMAC-SHA256) et le sens du message en données associées. Un message modifié, rejoué dans l'autre sens ou destiné à une autre transaction est refusé. Le tout passe en plus dans TLS.
  • Import d'un ancien trousseau WL : texte base64 de IV + AES-256-CBC(contrôle sur 8 octets + JSON), clair en Windows-1252 ou UTF-8.
